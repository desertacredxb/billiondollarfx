# BDFX operations readiness — 21 October 2026

This records configuration requirements and evidence. Code implementation does not confirm provider delivery or disaster recovery.

## Email delivery

The mailer preserves Gmail service when no SMTP_HOST is configured. It now verifies TLS certificates, uses bounded timeouts and defaults From to the authenticated EMAIL_USER/SMTP_USER address. A verified SMTP_FROM or EMAIL_FROM can override that default. Reply-To remains support@billiondollarfx.com. These changes do not prove inbox placement.

For a domain mailbox, configure SMTP_HOST, SMTP_PORT (465 implicit TLS or 587 STARTTLS), SMTP_USER, SMTP_PASS and a provider-authorized SMTP_FROM in the hosting secret manager. Keep existing credentials until the replacement provider is verified. Never commit secrets.

Validate a real received OTP's Authentication-Results and From/Return-Path alignment with the mail administrator. Confirm SPF/DKIM/DMARC against the actual sending service. Do not modify DNS from assumed provider settings. No OTP or email was generated by agent tests.

New support tickets persist notification state and retry team email up to three times, including reclaiming interrupted sends after ten minutes. A ticket remains saved when SMTP fails. Existing tickets without notification state are not retroactively emailed. The queue is at-least-once: a crash after SMTP acceptance can produce a duplicate notification; it cannot guarantee exactly-once delivery. Failed notifications remain marked failed for operational review.

## GA4 and Search Console

GA4 is disabled unless both NEXT_PUBLIC_GA4_ENABLED=true and a valid NEXT_PUBLIC_GA4_MEASUREMENT_ID are configured. No production ID has been verified or invented. Once the actual property is accessible, disable enhanced automatic measurement (including history pageviews and form interactions) before enabling this integration. Its manual events deliberately exclude query strings, account identifiers, customer details, arbitrary paths and trading data.

After enabling the verified property, optional analytics requires the visitor's explicit choice. Public pageviews use an allowlist. generate_lead occurs after a persisted contact confirmation; sign_up occurs after successful email verification, not when OTP is requested. No monetary conversion value is invented. Verify consent denial/revocation and the events in DebugView before marking key events in GA4. Preserve the existing Meta Pixel separately; this change does not certify its consent handling or enhanced matching settings.

The existing Google site-verification meta tag is retained. Ownership, property access, sitemap submission and indexing status must be verified in the actual Search Console property. A meta tag alone is not evidence that these are complete.

## Monitoring and backups

The backend /health endpoint returns HTTP 200 with a connected database and HTTP 503 when the database is unavailable. Render service srv-d39uut0dl3ps73aiomjg was inspected: HTTP healthCheckPath is empty and notifyOnFail is default. These are not proof of configured HTTP health monitoring, a chosen alert destination or tested failure notification. The available connector does not expose a service-health-path update and no Render CLI credential is configured in this workspace.

MongoDB Atlas was connected after installation. Both list-projects and list-clusters returned empty results. No existing production cluster, backup schedule, snapshot or restore operation was visible; no new cluster was created and production data was not queried.

Once the existing BDFX Atlas project is accessible, inspect the cluster tier, backup support, retention, recent successful snapshots and alert configurations. Restore a snapshot into an isolated destination and verify schema/indexes and representative integrity checks before recording recovery time and recovery point. A restore drill must never overwrite production. Do not upgrade a paid cluster or create an alternative production database without reviewing its cost and migration scope.

## Payment callback review — unresolved priority

Source review found public provider callback routes preceding user authentication in routes/paymentRoutes.js, which is expected only when provider authentication is enforced separately. The Cregis and Truepay9 callback handlers inspected do not visibly verify a provider signature before mutating payment state. Ramee/crypto decrypt payloads, but encryption alone must not be assumed to provide the required callback authentication for every provider. Existing callback paths can invoke balance updates.

This review does not prove exploitation or a live incident. Do not send forged callbacks, move money, guess signature formats or disable working providers. Obtain the current provider callback specification and merchant configuration, then implement signature verification over the required payload, timestamp/replay checks, amount/currency/order reconciliation and concurrency-safe ledger processing. Test with mocked balances or the provider sandbox before release. Payment callback code was not changed in this improvement release.
