# BDFX country learning SEO

Owner requested India, Pakistan and Vietnam as the primary SEO focus. The existing website gains an educational /learn hub and six fully rendered country/language guides: India English/Hindi, Pakistan English/Urdu, Vietnam English/Vietnamese. Urdu content uses RTL.

Each translation uses its own canonical and reciprocal language/region alternates within the same country. All seven public routes enter the sitemap and the existing consented GA4 public-path allowlist. The guide copies stay server-side; analytics imports only the small route manifest. The footer links the hub. Existing registration, KYC, payments, Buddy, analytics consent, private noindex paths and weekly blog publishing are preserved.

These are educational destinations with distinct local context, glossaries, official sources and education/help actions, rather than duplicate regional broker-registration funnels. They do not invent local authorization or service eligibility, offer returns or invite prohibited remittances. India cites RBI's3 February2022 notice; Pakistan cites the SBP18 May2022 advisory and SECP9 April2025 warning; Vietnam cites the government portal's10 July2026 response referring offshore-account eligibility questions to the State Bank. Native text is supplied alongside English; no forced IP/language redirect is introduced.

Measure country-level Organic Search sessions and landing pages through the existing consented analytics connection. Keep business traffic reports private. Country session rows can overlap and are not a replacement for the property-wide session total. Publication, sitemap inclusion and hreflang do not guarantee indexing or rankings.

Validation covers exact country/language scope, self-canonicals and reciprocal alternates, actual server-rendered native content/RTL, education-only actions, preservation of blog canonical filtering and the analytics path boundary. Run the existing frontend suite, TypeScript and production build before publication.

The managed preview wrapper currently appends Vite-specific flags to Next.js and exits on an unsupported --host flag. The application builds successfully with its unchanged Next.js scripts; check the real deployment in the browser after publication.
