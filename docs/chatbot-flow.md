# BDFX multilingual support flow

## Mobile engagement and optional OpenAI questions — 26 October 2026

The shared control is now a visible navy/gold BDFX Buddy launcher with the existing character and BDFX logo. A three-second welcome offers contextual getting-started, MT5 and support shortcuts, plus the existing six languages. Cards stack above the launcher within the mobile viewport and safe area. Touch scrolling resets the idle timer; a tab becoming visible can receive its first welcome. Existing pause, dismissal and two-prompt-per-tab limits remain. Field guidance reads only allowlisted field schema and safe error IDs.

The chat contains a separate AI question box when the backend reports a configured connection. Visitors explicitly opt in before submitting a typed question. Only that question, selected language and optional public FAQ index reach the fixed n8n workflow and existing server-side OpenAI provider. Questions, form values, browser tokens and account data are not added to Chat Reports. Revoking AI consent, closing the panel or switching language clears the local AI question/reply and cancels outstanding work. Generated answers are rendered as escaped plain text and have no ability to perform account or payment actions.

The backend uses one-use signed commands, bounded input/output and timeouts, per-IP limits and a durable daily request cap. No provider request runs merely because someone visits. Failure returns the existing guide and support links. A configured connection does not establish provider quota or successful live answers: the first controlled live round trip reached OpenAI but returned HTTP 429; account quota/rate diagnostics must be resolved before describing AI replies as working.

Optional saved sessions, contact consent and the protected Chat Reports remain available. A separate n8n aggregate report endpoint requires its own read-only credential; it does not expose contact details, private transcripts or financial records, and its workflow is not yet published.

## Implemented BDFX behavior

Four guided stages: language -> main topic -> subtopic/question -> automatic answer and relevant next action. English, Hindi, Bengali, Thai, Vietnamese and Indonesian have complete local UI/questions/answers. A visitor can switch languages at any stage; the chosen answer updates in that language. Seven topics and fourteen answers cover registration, email/WhatsApp codes, identity/country eligibility, deposits, withdrawals, MT5 tools, IB partners and support. FAQ search is local and does not send typed text to a backend. Unmatched text does not produce an invented answer.

The guide uses current BDFX public instructions, not the other broker's pricing, timings, campaigns or country policy. UAE nationality/residence/document restrictions remain explicit. Withdrawals retain the qualified 1–4-hour typical USDT window; the guide cannot approve a transaction, change KYC or inspect an account. Account-specific requests use existing signed-in support or the contact form; opening the widget does not create a lead/ticket or claim that a live agent is connected.

The floating BDFX Help control occupies the bottom right. At the owner's request, the separate floating WhatsApp icon is removed from the shared root layout; BDFX Help is the site's floating support control. The small nonmodal panel has labelled language/search controls, keyboard navigation, Escape/close behavior and a viewport-bounded scroll area. It loads no third-party chat script and makes no external AI request. The original release stored no activity or contact details; the owner subsequently requested admin counts and visitor details, implemented as the optional saved-session feature below. The existing legacy AI chat component remains disabled.

## Saved sessions and Chat Reports

The guide works without saving. A visitor may explicitly choose **Save session for support**; only subsequent allowlisted menu activity, chosen language and question IDs are sent to the existing backend. Search text, URLs, existing account tokens and arbitrary messages are not transmitted by this feature. **Ask the team to contact me** provides a separately acknowledged name/email/optional international phone/residence-country form. Submitted details are unverified, not automatically associated with a client account and do not constitute marketing permission. UAE enquiry restrictions remain in effect. No ticket or outbound message is generated by saving a session/contact request.

Administrators use **Chat Reports**, `/chat-reports`, to see saved sessions, contact requests, activity in the last five minutes, language and Dubai date/status filters, and selected guide questions/answers. Owners and existing support-authorized managers can review status/notes. Other managers, client JWTs and anonymous readers are rejected. The table refreshes every 30 seconds while visible. Counts are sessions, not unique people or live connections; unsaved visitors are not counted, guest details are unknown, and old unsaved chats cannot be recovered. This is a guided activity history, not a free-text chat transcript or a live-agent inbox.

Records and optional details expire 90 days after saving starts. Each browser session has a separate random write capability, kept only in component memory and stored as a hash on the server; it expires after 24 hours. Creation/activity/contact retries are idempotent, the atomic history limit is 100 events, public reads do not exist and admin responses never include capability data. Stopping saving blocks future events without deleting earlier records. Full backend contract and verification: `Billion_Doller_Backend/docs/chat-reports.md`. The guide data currently has version 1; preserve that catalog when introducing a future version so historical question IDs remain readable.
